# Отчёты Results Service: этап 6

Results Service публикует два маршрута на `http://127.0.0.1:8081`:

- `GET /runs/{id}/report` возвращает план, наблюдаемые счётчики, HTTP-коды, RPS и отдельные перцентили HTTP-ответов и транспортных исходов. `runState` берётся из финализации и может отсутствовать независимо от `reportState`.
- `GET /runs/{id}/timeline?after=0&limit=100` возвращает дельты принятых интервалов в порядке `sequence`. Передайте `nextAfter` следующему запросу; допустимый `limit` — 1–1000. При чтении незавершённого запуска перечитайте диапазон с начала, если пакет мог прийти не по порядку. Пропуски не заполняются нулями.

Счётчики и номера последовательности передаются десятичными строками. Итоговый RPS стартов вычисляется по длительности генерации без drain, RPS завершений — по окну от планового старта до завершения drain. Итоговые RPS не рассчитываются для неполного отчёта или запуска без интервала генерации. Перцентиль — верхняя граница бакета объединённой гистограммы; пустая выборка даёт `null`, а ранг выше последней границы — `overflow`.

`Collecting` означает, что ещё ожидаются пакеты. `Complete` требует всех номеров до единственного final, согласованных данных и отсутствия потерь. После дедлайна недостающие пакеты отражаются в `Incomplete` с причинами; поздние пакеты не меняют агрегаты. Некорректные сообщения и конфликтующие повторы записываются в карантин до подтверждения Kafka offset. Для сообщения без манифеста сохраняется диагностика, но не сами измерения; после пяти минут такой отчёт возвращает `MissingManifest`. Неизвестный идентификатор без событий возвращает `404`.

## Проверка

Из корня репозитория, с Python 3.10+ и Docker:

```sh
docker compose -p latencystorm-stage06 --env-file deploy/compose/.env.example -f deploy/compose/compose.yaml up --build --wait
python tests/infrastructure/stage05.py --project latencystorm-stage06
python tests/infrastructure/stage06.py
docker compose -p latencystorm-stage06 --env-file deploy/compose/.env.example -f deploy/compose/compose.yaml stop
```

Тест этапа 6 вставляет манифесты с известной выборкой в тестовую БД и публикует пакеты через Kafka. Он проверяет дедупликацию, перестановку последовательности, перцентили, пагинацию, пропуск перед финалом, карантин, поздний пакет и сохранность отчёта после перезапуска сервисов. Распределение измерений между несколькими агентами относится к этапу 7.
